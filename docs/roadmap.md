# 目標與路線圖

MiDiY 研究與逆向工程手邊的控制器，透過自訂映射輸出 MIDI，並公開協定、研究證據與實作供其他人參考。未來候選裝置包含 DJ Starlight、PS5、Xbox 手把；候選不代表已支援。

## 並行的使用方式

- **網頁直接使用**：連接控制器、擷取分析、編輯映射／模式／力度／回饋，即時轉譯並透過 Web MIDI 輸出，不需要翻譯盒。
- **翻譯盒獨立使用（規劃）**：控制器接盒子，盒子執行連線、解碼、映射與 MIDI 輸出。由網頁部署設定與必要支援程式，完成後不需網頁或 WebHID。部署對象是盒子，不修改控制器韌體。

初期盒子限於各一種 ESP32 與樹莓派硬體，板型／機型尚未決定。各平台可支援不同控制器與輸出子集；不要求 ESP32 執行 TypeScript。

## 三條獨立的連線

1. 控制器輸入：控制器如何連到瀏覽器或盒子，包含傳回 LED 等控制器命令。
2. MIDI 輸出：執行環境如何送 MIDI 到接收端。有線方式與 BLE MIDI 可分別擴充。
3. 部署管理：網頁如何把設定與程式部署到盒子，與演奏時的輸入／輸出分開。

接收端可包含 Windows、macOS、iPhone、iPad、Android、Linux 或其他設備，實際支援須依輸出方式與系統／軟體版本驗證。BLE MIDI 輸出不代表藍牙手把輸入已支援。

## 調整順序

| 階段 | 狀態 | 驗收 |
| --- | --- | --- |
| 第一輪：Runtime／Driver／研究工具分離與文件 | 已實作，驗證範圍見本輪紀錄 | 無 DOM 轉譯、現有相容性、網頁回歸 |
| 第二種控制器與共用事件／Profile 契約 | 未實作 | 以實體第二裝置驗證；本輪保留 v2，不增加舊格式遷移 |
| ESP32／樹莓派各選一種硬體 | 未決定 | 實測控制器輸入、供電與至少一種 MIDI 輸出 |
| 第一個獨立翻譯盒及部署流程 | 未實作 | 關閉網頁並重啟盒子後仍能演奏 |
| BLE MIDI 與其他接收端／平台組合 | 未實作 | 每個宣稱支援的組合都有實測證據 |

硬體可先做小規模可行性驗證，避免共用設計依賴未確認能力。每個平台只承諾已實作且有依據的功能子集。

後續部署區分 Mapping Profile、Runtime 的裝置／輸出路由設定，以及部署產物與版本清單；本輪不定義部署 wire format。跨平台以相同設定＋輸入序列→MIDI 序列作一致性驗證，傳輸與實際延遲另外測試。

樹莓派是否重用 TypeScript Runtime，待選型與輸入／輸出實測後決定；ESP32 可用原生韌體實作。
